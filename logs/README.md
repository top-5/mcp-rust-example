# MCP Server Logs

This directory contains logs generated by the MCP Rust server during operation.

## Log Files

### `mcp-server.log`
- **Purpose**: Main server output and information logs
- **Content**: 
  - Server startup/shutdown messages
  - Configuration details (host, port, endpoints)
  - MCP tool registrations
  - Request handling information
  - General operational status

### `mcp-server-error.log`
- **Purpose**: Error output and stderr capture
- **Content**:
  - Runtime errors and exceptions
  - Warning messages
  - Debug information when issues occur
  - Stack traces for troubleshooting

## Log Rotation

Currently, logs are appended to the files on each server restart. For production use, consider implementing log rotation to manage file sizes.

## Viewing Logs

### Real-time monitoring:
```bash
# Windows PowerShell
Get-Content logs/mcp-server.log -Wait -Tail 10

# View last 20 lines
Get-Content logs/mcp-server.log -Tail 20
```

### Check for errors:
```bash
# View error log
Get-Content logs/mcp-server-error.log

# Search for specific errors
Select-String "ERROR" logs/mcp-server.log
```

## Log Levels

The server uses `tracing` for structured logging with these levels:
- **INFO**: General operational information
- **DEBUG**: Detailed debugging information
- **WARN**: Warning messages
- **ERROR**: Error conditions

Set the `RUST_LOG` environment variable to control log verbosity:
```bash
# More verbose logging
$env:RUST_LOG = "debug"
cargo run --bin mcp-server

# Only errors and warnings  
$env:RUST_LOG = "warn"
cargo run --bin mcp-server
```

## Troubleshooting

### Common log patterns to look for:

**Server startup issues:**
```
ERROR: Address already in use
ERROR: Permission denied
```

**MCP protocol errors:**
```
ERROR: Failed to handle MCP request
ERROR: Tool execution failed
```

**VS Code integration issues:**
```
INFO: MCP client connected
ERROR: Authentication failed
```

### Log file permissions
If you encounter permission errors, ensure the `logs/` directory is writable:
```bash
# Check directory permissions
Get-Acl logs/

# The launcher utility should handle log file creation automatically
```

## Development Notes

- Log files are created automatically by the launcher utility
- Server output is redirected to these files when running in background mode
- When running server directly (`cargo run --bin mcp-server`), output goes to console
- Log files persist between server restarts for debugging purposes

## Security Considerations

- Log files may contain sensitive information depending on your tool implementations
- Consider log retention policies for production deployments
- Ensure appropriate file permissions in multi-user environments
